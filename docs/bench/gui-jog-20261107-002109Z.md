# Continuous and held-repeat jog — actual mount, 6 November 2026

**Both jog modes passed release, control focus loss, navigation away, and Stop.
Two release/focus defects were fixed. All original raw settings were restored.**

Unit: **K10CR2 serial 55551174, firmware 2.0.1, hardware revision 4**.
Testing ran **18:13–18:24 CST** (UTC−06:00); evidence filenames use 7 November UTC.
All actuator actions came from the production web GUI through our single
WinUSB/PyUSB/libusb/APT owner. No Kinesis, SDK, manufacturer runtime, firmware,
driver replacement or EEPROM write was used. Both recorder shutdowns and raw
restoration reported no loaded `clr`, `pythonnet`, `Thorlabs` or `Kinesis` module.

## Conditions and scope

The original baseline was zero counts, homed, enabled and idle. All five raw
settings groups were captured before changes. Temporary volatile settings were:

| Jog step / stop | 0.05° (6,827 counts) / profiled |
| Jog modes | Continuous (1), then Single step (2), then Continuous for focus retest |
| Backlash | 0 counts |
| Session rotation | Total Angle, quickest |

The recorder observed GUI requests, release reasons, operation boundaries, fresh
readbacks and every APT chunk. It added ±1° counted-travel and 4 s manual-duration
Stop guards. **Neither guard fired.** These are software guards, not independent
physical interlocks. Home is excluded from the travel guard: an explicit GUI Home
in the exploratory session at 18:17:53 reached −1.778562° before returning to zero.
Jog operations stayed between **−0.356587° and +0.423669°**; the stable final session
stayed between zero and +0.423669°.
Continuous jog used the production finite ±15,480° boundary target in Total mode;
the short holds and confirmed releases kept actual counted motion small.

All angles below are controller counters converted using 49,152,000 counts/rev.
They are not independent mechanical measurements. Operation duration includes
preflight, queries and cleanup; it is not a mechanical stop-time measurement.

For the focus tests, a real control click or navigation moved focus while the
Space hold was still pending. The journal recorded **`focus-out` before key-up**.
The Settings dialog was correctly refused during motion, while focus still moved
to its button and ended the lease. Navigation used a blank page and returned to
the same GUI/server; no synthetic DOM events or second USB owner were used.
Creating another in-app tab or hiding the in-app browser did not generate actual
window blur; those exploratory attempts ended by `key-up` and are retained as
ordinary release checks. **OS window switching/`window-blur` remains unverified.**

The continuous Stop click first moved focus and released the hold. Stop was then
accepted at the cleanup boundary, before the owner became idle. The owner completed
the release stop, restored its temporary move profile, and serviced the pending
explicit Stop. The trace contains two `0465` requests and two valid 14-byte `0466`
replies. This exercises the existing pending-Stop path, without lost cancellation
or queued motion. The finite-jog Stop instead interrupted the second step:
`MotionError(MotionCancelled)` reported **stop confirmed**, known stopped state,
and reconnect required. Explicit GUI disconnect/reconnect followed before any
further motion. No interrupted jog was replayed.

Every normal continuous release/focus case restored the temporary Move profile
exactly, confirmed by `0415` readback (minimum 0, acceleration 751, maximum 732,911).
Every finite-jog case sent **zero `046A` packets after its recorded release**, using
journal ordering rather than timestamp comparison. Release/focus cases did not
send a stop for finite jog: the already-issued step completed as specified.
All completed cases reported **`0x80000400`**, homed, enabled and not moving/homing.

## Issues fixed

1. **An extra finite jog could be queued if release arrived during the between-step
   position query.** Commit **`a64a305`** rechecks the hold immediately after that
   query. The regression first failed against the previous code with an unexpected
   second native jog, then passed after the fix. The bench repeat cases above
   confirm no further native jog followed release.
2. **Leaving the held button did not release its lease.** Commit **`8dfbd22`** adds
   control `focusout` release and records a release cause. The active manual control
   remains focusable while it owns motion; other manual commands remain disabled,
   and the owner still rejects additional starts. An intermediate asset-only
   version released immediately when the busy UI disabled the button; its no-motion
   attempt is retained in the exploratory journal. The stable retest verifies the
   complete fix for both jog modes.

The full offline suite passed **287 Python tests and one JavaScript event test**.
Ruff lint/format and JavaScript syntax checks passed. The JavaScript test executes
the actual asset with a simulated event environment; it is separate from the real
GUI/mount observations. A third-party Dash pytest-plugin deprecation warning
remains. The new test specifically checks a single token release and heartbeat
cleanup when focus leaves, with no duplicate release from subsequent key-up/blur.

## Restoration and final state

The GUI refreshed all five groups at zero, then disconnected and closed the bench
server. A sequential connection through our controller restored only velocity,
jog and backlash from the original raw baseline. Home/button values were checked
unchanged. The restoration trace contains no motion, enable/disable or EEPROM
command. **All five groups match exactly**, including original jog mode 2, step
13,653, velocity 109,951,163, acceleration 22,530 and backlash 136,533.

The normal GUI was restarted, connected and left at **zero counts, homed, enabled,
idle and error-free**, with original device settings and normal session defaults.
Connect loaded all five groups; the saved final GUI state matches the original
baseline. Only this task's generated scratch/test directories were removed;
the virtual environment and all historical bench captures were preserved.
