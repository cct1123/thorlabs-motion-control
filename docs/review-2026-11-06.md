# Repository review: 6 November 2026

## Original controller and GUI

Reviewed the library, protocol parser, WinUSB transport, CLI, Dash callbacks and
worker, packaging, nine notebooks, tests, documentation, and saved bench evidence.
The repository initially had no commits. Commit `2a2cefe` preserves the original
snapshot; it passed 132 offline tests. The following corrections are separate,
reviewable commits.

| Finding | Correction | Regression evidence |
| --- | --- | --- |
| Cancellation from the final progress callback could return motion success without honoring Stop. | Check cancellation before publishing successful completion. | Final-callback cancellation now raises `MotionError` and runs same-owner stop cleanup. |
| An observer raising `SystemExit` could leave motion without cleanup. | Handle `BaseException` once the actuator write may have started motion. | Observer exit retains its original cause and the stop result. |
| Invalid identity text raised a protocol error without requiring recovery. | Include decoding inside query failure handling. | A malformed model blocks subsequent operations until explicit reconnect. |
| Interrupted or expired enumeration leaked previously matched USB resources. | Dispose every retained/current candidate on enumeration failure, preserving the original exception. | Deadline and iterator-interrupt cases verify resource release without claiming an interface. |
| GUI Stop could be accepted after its last cancellation check and then lost when the worker released ownership. | Make Stop acceptance and owner release share one lock; service pending Stop on the same worker before release. | A synchronized final-readback race checks successful and failed stops. |
| Disconnect could release USB after an unconfirmed stop by skipping status in recovery. | Require explicit Stop confirmation before disconnect while physical state is unknown. | Failed stop retains the connection and Stop control; successful retry permits disconnect. |
| Shutdown could trust cached idle status despite later front-panel movement. | Query current status before release on a healthy connection; stop when busy. | Simulated fresh movement is stopped before the handle closes. |

Core corrections are in `61c5e0d`; GUI lifecycle corrections are in `eda8ede`.
Each new failure case was reproduced before its correction. An isolated snapshot
containing those commits passes **142 tests**, Ruff lint, and Ruff formatting.
Isolation prevented concurrently written settings/jog features from entering the
lifecycle commit. One warning comes from Dash's pytest plugin using a deprecated
pytest hook declaration.

The lockfile check, wheel and source-distribution builds, wheel asset/entry-point
inspection, and isolated wheel installation passed. The installed wheel serves its
stylesheet and disconnected GUI without importing `usb.core`. The test suite also
executes notebook defaults with external device access blocked and exercises
guarded examples using literal scripted APT responses.

## Evidence and limits

The bundled issue-48 protocol and K10CR2 manual match their recorded SHA256 hashes
and page counts. Relevant identity, position, home, absolute-move, stop, status,
and fault layouts were cross-checked in the local protocol. Stop pages 99-100 were
also rendered and visually inspected. This review did not change the original
actuator packet layouts or count scale. Both copies of each current manufacturer
reference were preserved; the reference inventory is in
[references/README.md](references/README.md).

Existing bench JSON and raw logs are historical evidence for the source versions
recorded there. Replaying them does not establish hardware acceptance of these
fixes. **No USB discovery, connection, motor command, driver change, or physical
motion was performed by this review.**

Controller status and counted positions do not independently establish mechanical
rest or angular accuracy. Front-panel actions can occur after any status sample;
fresh shutdown readback reduces the stale-state window but is not a hardware
interlock. Cross-process ownership, failed-link stopping, stop latency, enabling
from disabled state, independent angle/direction observations, and long-session
behavior retain the limits in [validation.md](validation.md).

## Settings and jog extension

The user explicitly expanded this review to include the concurrently developed
manual-style GUI and settings/jog extension. The core and GUI changes are separate
commits, `1fdfb1e` and `045d5d2`. The implementation addresses the following further
findings, each reproduced with a failing regression before correction:

| Finding | Final behavior |
| --- | --- |
| A late heartbeat could revive an expired browser hold. | Expired, released, mismatched, and inactive holds cannot be renewed. |
| Manual jog ignored cancellation from its final progress callback. | Cancellation enters same-owner stop cleanup and requires recovery. |
| Manual jog allowed observer `SystemExit` to escape without cleanup. | Observer exits retain their original cause and a separate stop result. |
| An unknown physical state with a clear recovery flag could enable motion. | Both UI gating and worker submission independently block unsafe continuation. |
| Starting a move left its modal over Stop; another modal could also obscure Stop during motion. | Accepted moves close the modal; active motion blocks new modal opening; dialogs also include Stop. |
| The manual link returned 404 outside the checkout. | The wheel includes the local manufacturer manual, served by the installed GUI. |
| Single-step jog did not reject a loaded acceleration above the documented limit. | Reject an above-limit profile before a jog command; also reject invalid mode/stop/profile fields and above-rating speed. |

Final hardening in `f1115d5` also checks the current counted interval before
fixed/manual movement and exposes the unrestored temporary-profile warning in GUI
errors. Stop remains accepted during readback, with a regression in `728b1ac`.
Commit `df147de` prevents Windows GUI servers from sharing an occupied loopback
port. The applied unit-factor display is corrected in `a92adfd`.

The final source passes **189 offline tests**, Ruff lint, and Ruff formatting on
Python 3.12.7. The GUI extension regressions include all five dialog entry points.
The settings tests cover literal velocity/jog frames, validation before writes,
readback mismatch recovery, explicit persistence requests, rotation modes,
counter bounds, locked/unverified groups, and temporary drive-profile restoration.

An independent browser simulation confirmed connection, settings-tab switching,
applying session options, motion submission, immediate Stop access, rejection of
modal opening during motion, confirmed simulated stop, reconnect gating, and
disconnect. The simulation used an injected `FakeMount`; it did not use USB.
The temporary review server was shut down after inspection. The extension's
implementation browser checks use a separate simulated APT transport.

Wheel and source-distribution builds and isolated installation passed. The wheel
serves the stylesheet, hold script, and local PDF without importing `usb.core`.
The source distribution excludes the environment, Git metadata, and temporary
build/cache files. These software checks do not establish physical behavior.
The hold script also passes Node's syntax check. An independent historical-record
audit is retained in [the protocol evidence review](reviews/protocol-evidence-20261106.md).

The new protocol mappings, K10CR2 velocity/acceleration scaling, manual drive/jog,
multi-turn routing, disable/identify, settings writes, and EEPROM persistence
remain **bench-unverified**. The scale table still names K10CR1; a K10CR2 readback
does not independently prove physical speed. Temporary profiles can remain changed
after a failed cleanup or restore. Partial application of several settings groups
is possible on communication failure; no rollback or motion replay is attempted.
See [the GUI contract](gui-manual.md) for the manufacturer-page mapping and explicit
unavailable/locked functions. All communication remains our own WinUSB/APT code.
